The engine

Every layer of the stack, rebuilt.

No wrapper around someone else's runtime. Custom weight format, custom kernels, custom memory scheduler — compiled for your exact GPU at load time.

CNQ4.5

4.5-bit weights that behave

FP4 payloads with UE4M3 subblock scales, MSE-fitted per 16-element block. 2.17 % clipped elements, layer-level error 0.09 rel L2 — measured, not promised.

4-bit payloadfp8 scale / 16−21 % MSE vs ceiling
sm_120a

Tensor cores all the way down

Every dense and routed GEMV runs m16n8k64 FP4 MMA — 110 kernels NVRTC-compiled at load out of one module, tuned to your GPU, with the naive path kept as fallback.

residency

The right experts, always hot

A traffic-trained hot-set pins 155 of 512 experts per layer in VRAM. Everything else streams zero-copy from pinned memory at ~25 GB/s — the router never waits.

262,144 tokens of memory

FP8 key-value cache and GDN state under one budget manager. The loader clamps the cache, never your context — 200k is the floor, not the ceiling.

One launch per token

The whole decode step — attention, MoE, head, argmax — is captured once and replayed as a CUDA graph. Roughly a thousand kernel launches collapse into one.

Quickstart

Three commands. Then it's yours.

# Rust toolchain + CUDA 13.3 toolkit, that's it $ git clone https://github.com/nibor1896/crow-nest $ cd crow-nest/engine && cargo build --release --bin serve # 110 kernels compile for your GPU on first launch
# CNQ4.5 container · 262k context · OpenAI-compatible $ tools/serve-linux.sh --port 8099 ✓ container loaded 31.2 GiB VRAM (hot · 155/layer) ✓ listening http://127.0.0.1:8099
from openai import OpenAI client = OpenAI(base_url="http://127.0.0.1:8099/v1", api_key="crow") stream = client.chat.completions.create( model="qwen3.8-flash-next", messages=[{"role": "user", "content": "Explain entropy like I'm five"}], stream=True, ) for chunk in stream: print(chunk.delta, end="")
